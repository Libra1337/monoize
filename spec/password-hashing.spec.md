# Password Hashing Specification

## 0. Scope

This specification defines password hashing and verification for dashboard users.

## 1. Algorithm

PH1. Monoize MUST hash each new password with `Argon2::default()` and a salt generated by `SaltString::generate(OsRng)`.

PH2. Monoize MUST verify a password against the complete persisted PHC hash with `Argon2::default()`.

PH3. A password mismatch MUST produce `false`. An invalid persisted PHC hash MUST produce an error.

## 2. Async execution

PH4. An async request path MUST execute each Argon2 hash or verification operation through `tokio::task::spawn_blocking`. It MUST NOT execute Argon2 on the Tokio worker that polls the request future.

PH5. The caller MUST await the blocking task before it reads or writes password-dependent state. A blocking-task join failure MUST produce an error and MUST NOT create a session, insert a user, or persist a password update.

PH6. User creation and non-transactional user updates MUST finish password hashing before the first database write for that operation.

PH7. The atomic admin user update MUST finish password hashing before it acquires the database write connection and begins the transaction.

## 3. Login verification work

PH8. After a login request passes CAPTCHA and username-prefix validation, the handler MUST execute exactly one Argon2 password verification before it returns an account-dependent response.

PH9. If the username does not identify a user, the handler MUST verify the submitted password against a fixed valid Argon2 PHC hash. It MUST then return HTTP `401` with code `invalid_credentials`.

PH10. If the username identifies a disabled user, the handler MUST complete the Argon2 password verification before it returns HTTP `403` with code `account_disabled`.
