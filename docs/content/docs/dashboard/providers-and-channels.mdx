## Concepts

- A **Provider** belongs to one Group. It defines routing order, pricing defaults, health policy, and an ordered transform chain.
- A **Channel** is the Provider's single upstream endpoint. It holds the upstream type, Base URL, credential, model mappings, and timeout.

A request first selects a Provider, then selects a Channel inside it. See [Routing and Reliability](/en/docs/routing) for the selection rules.

## Create a Provider

1. Open **Providers** in the sidebar.
2. Click the create button and enter a name.
3. Select one Group and configure the embedded Channel.
4. Confirm that the Provider and Channel names can appear on public pages.
5. Set `channel_max_retries` and `channel_retry_interval_ms` when the retry defaults do not fit.
6. Keep `circuit_breaker_enabled` on unless you have a reason to disable it.

## Configure the Channel

1. Open the Provider and select **Channel**.
2. Select the upstream type: `responses`, `chat_completion`, `messages`, `gemini`, `openai_image`, or `replicate`.
3. Enter the upstream base URL and API key.
4. Optional: set `proxy_url` to override the process-level upstream proxy.

When you edit a Channel later, leave the API key field empty to keep the stored key.

## Map models

The embedded Channel lists the logical models it serves. A model mapping has:

- `redirect`: the real upstream model name. Leave empty to send the logical name unchanged.
- a pricing Profile mode: inherit the Provider default, override it, or mark the mapping unpriced.
- an optional multiplier override. Otherwise, the mapping inherits the Provider multiplier.

A logical model routes to a Provider only when its Channel is enabled and the mapping has complete pricing.

Save the Provider even when a pricing warning appears. Read each warning for the logical model and missing usage classes. Add the missing rates before routing traffic.

## Provider transforms

A Provider can hold an ordered list of transform rules. They run on every request that the Provider serves, after Provider selection and before upstream encoding. See [Transforms](/en/docs/transforms).

## Wholesale Providers

An `agent` Group serves reseller accounts. It does not hold ordinary Providers.

1. Create a Group of the `agent` class first: on **Providers**, switch the **Catalog scope** to `agent`, or create it inline from the wholesale dialog when none exists.
2. Click **Add Wholesale Provider**.
3. Select one existing Provider from the `standard`, `enterprise`, or `private` classes as the source.
4. The source Channel configuration and model mappings are copied once. Later source changes do not propagate.
5. Every model starts at the source multiplier. Change any multiplier before you save. Edit multipliers later with the ordinary Provider editor.
6. The wholesale Provider reuses the billing Profile of its source. Its own multipliers set the wholesale price.

Only agent accounts see agent Groups, create keys in them, and use their multipliers. The Model Marketplace of an agent account follows the same rules as the other classes.

## Groups

Every Provider belongs to exactly one Group. API keys route only to Providers in their allowed Groups. Use Groups to separate user tiers or environments.

Confirm public exposure when you create or rename a Group. The public Marketplace and status page show the confirmed Group, Provider, and Channel names.
