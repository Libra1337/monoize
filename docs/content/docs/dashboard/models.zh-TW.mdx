## 邏輯模型

客戶端請求的是邏輯模型名稱。Monoize 把這個名稱解析到你的 Provider 和 Channel。客戶端看到的名稱不需要與上游廠商的名稱一致。

一個邏輯模型可以對應到多個 Provider 各自的 Channel。客戶端無需任何修改即可獲得容錯移轉。

![模型資料庫](/images/en/models.webp)

## 重新導向

Channel 的模型條目可以用 `redirect` 指定真實的上游模型名稱。

範例：客戶端呼叫 `my-fast-model`。一個 Provider 將其重新導向到 `gpt-4o-mini`，另一個 Provider 將其重新導向到 `claude-3-5-haiku-20241022`。計費和日誌始終顯示邏輯名稱。

## 模型中繼資料與定價

**模型資料庫**頁面儲存模型中繼資料和 Billing Profile 費率記錄。Monoize 從 [Models.dev](https://models.dev) 匯入中繼資料和價格建議。

計費規則：

1. 選擇模型對應的有效 Billing Profile；
2. 為上游模型或邏輯模型選擇完整費率矩陣；
3. 套用模型倍率覆寫或 Provider 倍率。

每筆費率記錄同時保存價格和價格貨幣。手動輸入的費率預設以 `CNY / 1M tokens` 計價。從 Models.dev 匯入的費率保持 `USD`。

價格編輯器帶 `CNY`/`USD` 貨幣選擇;輸入的數字按所選貨幣直接解釋,不做匯率換算。從 Models.dev 匯入的費率保持 `USD`。

編輯器為每個用量類別(含快取寫入 5m 與 1h)設定離峰價和可選尖峰價。尖峰價僅在北京時間週一至週五 `09:00–12:00` 與 `14:00–18:00` 生效。尖峰價留空則始終按離峰價計費。

Monoize 用目前的 CNY/USD 匯率快照換算 `CNY` 價格，並以奈米美元（nano-dollar）為單位把費用累計到每個使用者的流水帳。如果某個模型使用 `CNY` 價格而目前沒有可用的匯率快照，該模型的請求回傳 `model_pricing_required`，不會按估算匯率扣費。

## 模型列表

`GET /v1/models` 回傳呼叫方 API 金鑰可用的邏輯模型。結果反映金鑰的模型限制和群組歸屬。

## 模型萬用字元

變換規則和部分限制支援模型萬用字元：

- `*` 匹配任意長度的字元序列，包括空序列。
- `?` 恰好匹配一個字元。
- 匹配區分大小寫，並錨定整個模型名稱。

範例：`gpt-4*` 匹配 `gpt-4o` 和 `gpt-4o-mini`，不匹配 `o4-mini`。


## 管理計費 Profile

開啟工具列的 **Profile 管理**。每個 Profile 顯示模型數與費率數。

- **複製**將全部費率列複製到新 Profile 名下。
- **刪除**移除該 Profile 及其全部費率列。被匹配規則或 Provider 參照的 Profile 會拒絕刪除,並內聯顯示原因。

## 同步價格

開啟工具列的 **同步**,選擇 **同步 models.dev** 或 **同步目錄**。同步完成後,報告顯示更新了多少模型、移除了多少,以及哪些模型保留了手動價格。手動價格不會被同步覆蓋。
