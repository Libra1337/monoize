## Store を開く

`/dashboard/store` で **Store** を開きます。**残高**、**プラン**、または**コード引き換え**を選択します。

![Store](/images/en/store.webp)

通貨コントロールで CNY または USD を表示します。この操作は、残高、今月の使用量、価格、ボーナス、受取額、プラン上限額を同時に更新します。

Monoize は USD/CNY レートを最大 15 分間隔で更新します。更新に失敗した場合は、最後の有効なレートを保持します。

## 残高をチャージする

1. チャージ商品を選択するか、カスタム金額を入力します。
2. チャージ額、ボーナス額、受取額を確認します。
3. 有効な支払い Channel を 1 つ選択します。
4. 注文を作成します。

Monoize は Provider に接続する前に支払い試行を保存します。Stripe はホスト型 Checkout ページを開きます。

Alipay は署名済みの公式支払いフォームを送信します。WeChat Native は読み取り可能な QR コードを表示します。WeChat H5 は公式モバイル支払いページを開きます。

Provider の結果が不明な場合は、別の支払い試行を作成しないでください。Monoize が既存の支払い試行を照合するまで待ちます。

Checkout の終了後、Store は注文を 2 秒ごとに確認します。支払いと履行の完了、注文の終了、または注文の期限切れで確認を停止します。

`/dashboard/orders` で注文を確認します。支払い状態と履行状態を個別に確認します。

Monoize は Channel の支払いを検証した後にのみ残高を付与します。管理者は未払いの注文を支払い済みまたは履行済みに変更できません。

## Stripe コールバックを設定する

Stripe Webhook エンドポイントを `https://lynshen.org/api/store/callbacks/{channel_id}` に設定します。`{channel_id}` を Stripe Channel ID に置き換えます。

`checkout.session.completed` と `checkout.session.async_payment_succeeded` を購読します。エンドポイント署名シークレットを暗号化された Stripe 認証情報に保存します。

## Alipay コールバックを設定する

Alipay 非同期通知 URL を `https://lynshen.org/api/store/callbacks/{channel_id}` に設定します。`{channel_id}` を Alipay Channel ID に置き換えます。

Store Management で Alipay アプリ ID、販売者 ID、加盟店秘密鍵、Alipay 公開鍵、環境を保存します。Monoize は RSA2 を検証し、検証済みイベントを保存した後だけ `success` を返します。

## WeChat Pay コールバックを設定する

WeChat Pay 通知 URL を `https://lynshen.org/api/store/callbacks/{channel_id}` に設定します。`{channel_id}` を WeChat Pay Channel ID に置き換えます。

加盟店 ID、アプリ ID、API v3 キー、加盟店証明書シリアル、加盟店秘密鍵、プラットフォーム証明書シリアル、プラットフォーム公開鍵を保存します。Monoize は履行前にプラットフォーム署名を検証し、支払いリソースを復号します。

## プランを購入する

プランと支払い Channel を選択します。1 つのプランに複数の上限期間を同時に適用できます。期間には、5 時間、12 時間、日、週、月、または任意の整数時間を指定できます。

Monoize はプラン上限額を CNY で保存します。Store は、四捨五入した整数の CNY または USD 金額を表示します。

## SQLite でプランを有効にする

SQLite のクォータ Gate を変更する前に、Monoize アプリケーションを停止します。`MONOIZE_DATABASE_DSN` に対象の SQLite データベースを設定します。

合格した演習 manifest を `next` スロットにインポートします。

```bash
monoize-store-ops quota-gate import --slot next --manifest ./quota-manifest.json
```

コマンド出力から互換性 fingerprint を確認します。新しいアプリケーションバージョンを起動する前に、インポートした manifest を昇格します。

```bash
monoize-store-ops quota-gate promote --expected-fingerprint <fingerprint>
```

このコマンドは、PostgreSQL、サイズ超過の manifest、不正な JSON、現在の SQLite 環境と一致しない manifest を拒否します。

## コードを引き換える

**コード引き換え**に未使用のコードを入力します。コードは残高を追加するか、プランを有効にします。引き換えでは支払い Channel を使用せず、注文も作成しません。

## Store を管理する

管理者は `/dashboard/store-admin` を開きます。4 つのタブで商品、支払い Channel、注文、引き換えコードを管理します。

- CNY と USD のカスタムチャージ範囲を個別に設定します。
- Alipay、WeChat Pay、Stripe、または HTTP 下書き Channel を追加します。組み込みアイコン、HTTPS 画像 URL、またはアップロード画像を使用します。
- 既存の公式 Channel を開きます。すべての認証情報と現在の管理者パスワードを入力します。**認証情報を置換**を選択します。Monoize は新しいバージョンを暗号化し、以前のバージョンと Channel を無効にします。
- Milestone 1 では HTTP Channel を無効のままにします。
- 支払い状態と履行状態を個別に確認します。手動完了操作は使用しません。
- 1 回に 1 から 20 個の単回使用コードを生成します。Monoize が平文コードを表示したときに保存します。
- **支払いチャネル**タブの上部から**プライバシー記録**と**保持**を開きます。
- Alipay、WeChat Pay、または Stripe の Channel 行で盾のボタンを選択し、**チャネル準備状況**を開きます。HTTP Channel 行にこのボタンは表示されません。

## プライバシー記録を確認する

本番のチェックアウトとコールバックには、現行の承認済み Store プライバシー記録が必要です。再審査の間隔は 365 日を超えてはいけません。

`/dashboard/store-admin` で**商店管理**を開きます。**支払いチャネル**タブを選択します。**プライバシー記録**を選択します。

![Store privacy records](/images/en/store-privacy-records.webp)

一覧の各記録は、ポリシーバージョン、管轄区域、許可地域、承認状態、次回の再審査日を表示します。保存した記録は編集できません。

ポリシー更新を承認したら記録を追加します。次の値を入力し、**記録を追加**を選択します。

| 項目 | 有効な値 |
| --- | --- |
| **ポリシーバージョン** | 1 から 64 バイト |
| **管轄区域** | 1 から 128 バイト |
| **許可地域（カンマ区切り）** | 重複しない 1 から 32 個の値 |
| **法的根拠** | 1 から 512 バイト |
| **証跡 SHA-256 ダイジェスト** | 小文字の 16 進数でちょうど 64 文字 |
| **財務記録の保持日数** | 1 から 36500 |
| **期限切れ許可の保持時間** | 1 から 24 |
| **再審査までの日数** | 1 から 365 |

フォームは管轄区域と許可地域に `CN`、財務記録の保持に 2557 日（7 年）、期限切れ許可の保持に 24 時間、再審査までに 90 日を初期表示します。各値をポリシーが承認した値に置き換えます。

Monoize は審査者、承認時刻、次回の再審査日を設定します。Monoize はフォームに現れない 3 つの保持期間も固定します。コールバック本文は 30 日、ネットワークメタデータは 90 日、引換監査は 730 日です。

## チャネル準備状況を関連付ける

準備プロファイルが現行の承認済みプライバシー記録を参照するまで、Channel は利用不可のままです。

![Store payment Channels](/images/en/store-governance.webp)

Alipay、WeChat Pay、または Stripe の Channel 行で盾のボタンを選択します。**プライバシー記録**を選択します。署名付きコールバック試験に合格した後だけ**コールバック検証済み**を有効にします。対応通貨、チェックアウト動作、通貨ごとの金額範囲、ライセンス、実行、可用性の各証跡ダイジェスト、そして 1 から 90 日の有効期間を設定します。**保存**を選択します。

プライバシー記録が 1 件もない間、保存操作は無効のままです。先に**プライバシー記録**で記録を追加します。

各 Channel 行は設定状態と実効状態を表示します。利用不可の Channel は理由コードを表示します。例は `privacy_gate_pending`、`readiness_profile_missing`、`readiness_profile_expired`、`callback_verification_pending`、`compliance_missing`、`capability_<kind>_missing` です。

支払い条件の確認と加盟店能力の記録にダイアログはありません。次の管理者エンドポイントを使用します。

- `PUT /api/dashboard/store/admin/payment-channels/{id}/compliance` は現行の Store 支払い条件を確認します。スコープ `compliance_confirm` の 5 分間の再認証許可が必要です。
- `PUT /api/dashboard/store/admin/payment-channels/{id}/capabilities/{capability}` は加盟店能力を 1 件記録します。状態、環境、チャネル商品、証跡ダイジェスト、有効期限を含みます。

## データ保持を理解する

Monoize は Store Primary で毎日 03:00 UTC に上限付きの保持ジョブを 1 回実行します。Replica はこのジョブを実行しません。各実行は開始時点で現行の承認済みプライバシー記録を使用します。

次の保持期間がすべての記録に適用されます。

- コールバック本文：30 日。
- ネットワークメタデータ（送信元 IP と User-Agent）：90 日。
- 引換コードの表示、コピー、エクスポートの監査：730 日。
- 期限切れ再認証許可のハッシュ：期限切れ後、**期限切れ許可の保持時間**が経過するまで。
- 財務記録：**財務記録の保持日数**。

1 回の実行は 5 つのデータクラスごとに、保持対象外のルート記録を最大 500 件まで検査して変更します。データクラスは `raw_callback_bodies`、`network_metadata`、`financial_records`、`redemption_audits`、`expired_reauth_grants` です。財務ルート記録を 1 件削除すると、その支払い試行、イベント適用、返金、返金照会の再試行、報酬回収行、回収請求行も削除します。実行は有効なエンタイトルメントとその発行記録を残します。

各実行は 1 つのトランザクションで完了します。失敗するとその実行の削除をすべてロールバックします。変更のないデータに対して実行を繰り返しても、消去済みの項目は変わりません。前回の実行が候補を削除していても失敗しません。

支払いデータ、コールバック証跡、バックアップ、ログ、暗号鍵は、プライバシー記録の許可地域内にとどまります。証跡の読み取り、エクスポート、保持の上書き、法的保持の各操作は、実行者、役割、範囲、理由、時刻、結果を記録する変更不可のアクセス監査を書き込みます。

## 保持を手動で実行する

**商店管理**を開きます。**支払いチャネル**タブを選択します。**保持**を選択します。

![Store retention](/images/en/store-retention.webp)

ダイアログは連続失敗、チェックアウト状態（**開放**または**停止中**）、実行の件数、法的保持の件数を表示します。

**現在のパスワード**と**理由**を入力します。**保持を実行**を選択します。Monoize はスコープ `retention_operation` の 5 分間の再認証許可を取得し、上限付きの実行を 1 回開始します。

実行が既に進行中の場合、要求は HTTP `409` とコード `retention_run_active` を返します。成功した実行は連続失敗を 0 に戻します。失敗または中断した実行はこの値を 1 増やします。

## 法的保持を適用する

法的保持は 1 つのデータクラスで指定した識別子の削除を停止します。**保持**ダイアログは法的保持の件数を表示します。ここで法的保持を作成することはできません。

`POST /api/dashboard/store/admin/retention/legal-holds` で法的保持を作成します。この要求には管理者セッション、Store Primary、スコープ `legal_hold` の 5 分間の再認証許可が必要です。JSON 本文は `data_class`、`identifiers`、`reason`、`requesting_authority`、`requester_id`、`approver_role`、`expires_at`、`extends_hold_id` を含めます。

- `data_class` は 5 つの保持データクラスのいずれかにします。
- `identifiers` は重複しない 1 から 100 個の値を含めます。各値は最大 255 バイトです。
- `approver_role` は `privacy` または `legal` にします。
- `requester_id` は認証済み管理者と異なる値にします。その管理者が承認者です。
- `expires_at` は未来の RFC3339 時刻にします。
- 初回承認では `extends_hold_id` を `null` にします。延長は、データクラスと識別子が同一の法的保持を参照し、より遅い期限を使用します。

法的保持は、開始時刻が評価時刻以前で、評価時刻が期限より前の間だけ適用されます。期限を過ぎると操作なしで終了します。法的保持は削除済みデータを復元しません。保存済みの保持行を更新、削除、再有効化、変更する操作はありません。延長は新しい法的保持と新しい承認監査を追加します。

## チェックアウト停止を解除する

実行の失敗によって連続失敗が 3 に達し、チェックアウトがまだ停止していない場合、Monoize は重大な保持アラートを 1 件作成し、チェックアウトを停止します。

チェックアウトの停止中、新しい注文と新しい支払い試行は HTTP `503` とコード `store_retention_paused` を返します。既存の注文または終了状態の支払い試行に対する冪等な再送は、以前の結果をそのまま返すことがあります。コールバックの受信、照合、返金、保持の各操作は利用できます。

アプリケーションを再起動しても、カウンター、アラート、停止は保持されます。実行が成功しただけでは停止は解除されません。

停止を解除するには**保持**を開きます。ダイアログはチェックアウトの停止中だけ**証跡 SHA-256 ダイジェスト**の項目を表示します。**現在のパスワード**、**理由**、ダイジェストを入力します。**アラートを封じ込める**を選択します。

Monoize は封じ込めを記録し、アラートを封じ込め済みにして、チェックアウトを再開します。封じ込めは連続失敗の値を変更しません。その後に実行が失敗すると、再びチェックアウトを停止することがあります。有効で未封じ込めのアラートがない場合、封じ込め要求は HTTP `409` とコード `retention_containment_unavailable` を返します。
