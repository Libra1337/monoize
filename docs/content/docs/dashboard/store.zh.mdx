## 打开商店

在 `/dashboard/store` 打开**商店**。选择**余额**、**套餐**或**兑换码**。

![商店](/images/zh/store.webp)

使用货币控件显示人民币或美元。此控件会同时更新余额、本月用量、价格、赠送、实得金额和套餐额度。

Monoize 最多每 15 分钟刷新一次美元兑人民币汇率。刷新失败时，Monoize 保留最后一次有效汇率。

## 充值余额

1. 选择充值商品，或输入自定义金额。
2. 检查充值金额、赠送金额和实得金额。
3. 选择一个已启用的支付 Channel。
4. 创建订单。

Monoize 在联系 Provider 前保存支付尝试。Stripe 随后打开其托管的 Checkout 页面。

支付宝提交已签名的官方支付表单。微信 Native 显示可扫描的二维码。微信 H5 打开官方移动支付页面。

Provider 结果未知时，不要创建另一个支付尝试。等待 Monoize 对账现有支付尝试。

Checkout 结束后，商店每两秒检查一次订单。支付和履约完成、订单关闭或订单过期后，检查停止。

在 `/dashboard/orders` 查看订单。分别检查支付状态和履约状态。

Monoize 仅在验证渠道支付后发放余额。管理员不能把未支付订单标记为已支付或已履约。

## 配置 Stripe 回调

把 Stripe Webhook 端点设为 `https://lynshen.org/api/store/callbacks/{channel_id}`。用 Stripe Channel ID 替换 `{channel_id}`。

订阅 `checkout.session.completed` 和 `checkout.session.async_payment_succeeded`。把端点签名密钥保存到加密的 Stripe 凭据中。

## 配置支付宝回调

把支付宝异步通知地址设为 `https://lynshen.org/api/store/callbacks/{channel_id}`。使用支付宝 Channel ID 替换 `{channel_id}`。

在商店管理中保存支付宝应用 ID、卖家 ID、商户私钥、支付宝公钥和环境。Monoize 验证 RSA2，并仅在保存已验证事件后返回 `success`。

## 配置微信支付回调

把微信支付通知地址设为 `https://lynshen.org/api/store/callbacks/{channel_id}`。使用微信支付 Channel ID 替换 `{channel_id}`。

保存商户号、应用 ID、API v3 密钥、商户证书序列号、商户私钥、平台证书序列号和平台公钥。Monoize 在履约前验证平台签名并解密支付资源。

## 购买套餐

选择套餐和支付 Channel。一个套餐可以同时应用多个额度周期。周期可以是 5 小时、12 小时、每日、每周、每月或自定义整数小时。

Monoize 以人民币存储套餐额度。商店会把额度显示为四舍五入后的整数人民币或美元金额。

## 为 SQLite 启用套餐

更改 SQLite 配额 Gate 前，停止 Monoize 应用。把 `MONOIZE_DATABASE_DSN` 设为目标 SQLite 数据库。

把已通过演练的 manifest 导入 `next` 槽位：

```bash
monoize-store-ops quota-gate import --slot next --manifest ./quota-manifest.json
```

从命令输出中读取兼容性 fingerprint。启动新应用版本前，推广已导入的 manifest：

```bash
monoize-store-ops quota-gate promote --expected-fingerprint <fingerprint>
```

此命令会拒绝 PostgreSQL、过大的 manifest、无效 JSON，以及与当前 SQLite 环境不匹配的 manifest。

## 使用兑换码

在**兑换码**中输入一个未使用的兑换码。兑换码可以增加余额或激活套餐。兑换过程不使用支付 Channel，也不创建订单。

## 管理商店

管理员打开 `/dashboard/store-admin`。使用四个标签管理商品、支付 Channel、订单和兑换码。

- 分别设置人民币和美元的自定义充值范围。
- 添加支付宝、微信支付、Stripe 或 HTTP 草稿 Channel。使用内置图标、HTTPS 图片链接或上传图片。
- 打开一个现有的官方 Channel。填写全部凭据字段和当前管理员密码。选择**替换凭据**。Monoize 加密新版本、停用旧版本并禁用此 Channel。
- 在 Milestone 1 中保持 HTTP Channel 停用。
- 分别查看支付状态和履约状态。不要使用人工完成操作。
- 一次生成 1 至 20 个单次兑换码。Monoize 显示明文时立即保存。
- 在**支付渠道**标签页标题栏打开**隐私记录**和**保留策略**。
- 在官方 Channel 行选择 **Governance**。打开**支付合规**、**商户能力**或**渠道就绪状态**。

## 隐私与数据治理

生产环境 checkout 和回调需要当前已接受的 Store 隐私记录。复审间隔不得超过 365 天。

在 `/dashboard/store-admin` 打开**商店管理**。选择**支付渠道**标签页。选择**隐私记录**。

查看现有记录。每条记录显示政策版本、司法辖区、允许区域、接受状态和下次复审日期。

批准策略更新后创建新记录。输入政策版本、司法辖区、允许区域、法律依据和证据 SHA-256 摘要。设置财务记录保留天数、过期授权保留小时数和复审间隔。记录创建后不可修改。

在该 Channel 行选择 **Governance**。选择**渠道就绪状态**。通过该对话框关联隐私记录。若无隐私记录，在就绪状态空状态中选择**打开隐私记录**。readiness profile 未引用当前已接受记录时，Channel 保持不可用。

生产 checkout 还需要每个官方 Channel 的当前 Store 支付条款确认。

在该 Channel 行选择 **Governance**。选择**支付合规**。查看 Store 支付条款确认摘要和当前条款版本。勾选确认复选框。输入 Admin 密码。选择**确认当前条款**。

有效 Channel 可用性还需要当前商户能力记录。

在该 Channel 行选择 **Governance**。选择**商户能力**。选择能力类型。设置状态、环境、Provider 产品和证据摘要。Monoize 记录验证并设置到期时间。

以下保留周期适用于每条记录：

- 回调原文：30 天
- 网络元数据（source IP 和 User-Agent）：90 天
- 兑换 reveal、copy 和 export 审计：730 天
- 过期 reauthentication grant 哈希：过期后 24 小时内

支付数据、回调证据、备份、日志和加密密钥必须保留在隐私记录的允许区域内。

每次证据读取、导出、保留覆盖和法律保留操作都会写入不可变的访问审计。

## 数据保留与删除

Monoize 每天在 Store Primary 的 03:00 UTC 运行有界保留任务。Replica 不运行此任务。

打开**商店管理**。选择**支付渠道**标签页。选择**保留策略**。

对话框显示连续失败次数、结账暂停状态、运行记录数和法律保留数。

需要立即清理时手动运行保留。输入当前密码和原因。选择**运行保留**。Monoize 按数据类别分批删除或清除过期数据。

每次运行每个数据类别最多处理 500 条未 hold 的根记录。删除财务根记录时也会删除关联子记录。有效 entitlement 不会被删除。

运行成功后连续失败次数重置为零。

## 法律保留与删除失败暂停

法律保留会暂停指定数据类别中特定标识符的删除。通过 `POST /api/dashboard/store/admin/retention/legal-holds` 创建保留。请求需要 scope 为 `legal_hold` 的五分钟 reauthentication grant。

每个保留需要不同 approver、原因、请求机构、强制到期时间，以及 1 至 100 个标识符。数据类别必须是以下之一：`raw_callback_bodies`、`network_metadata`、`financial_records`、`redemption_audits` 或 `expired_reauth_grants`。到期后保留自动停止。保留不会恢复已删除数据。延长保留需要创建新的审批记录。

**保留策略**对话框显示法律保留数，但不创建保留。

三次连续保留运行失败后，Monoize 创建严重告警并暂停新结账。现有订单和回调 ingestion 继续运行。新订单和 payment attempts 返回 HTTP `503`，code 为 `store_retention_paused`。

通过遏制清除结账暂停。结账暂停时打开**保留策略**对话框。输入当前密码、原因和证据 SHA-256 摘要。选择**遏制告警**。Monoize 记录遏制、标记告警为已遏制，并恢复结账。后续运行再次失败时结账可能再次暂停。
