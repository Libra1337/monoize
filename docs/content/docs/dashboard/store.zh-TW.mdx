## 開啟商店

在 `/dashboard/store` 開啟**商店**。選擇**餘額**、**方案**或**兌換碼**。

![Store](/images/en/store.webp)

使用貨幣控制項顯示人民幣或美元。此控制項會同時更新餘額、本月用量、價格、贈送、實得金額和方案額度。

Monoize 最多每 15 分鐘更新一次美元兌人民幣匯率。更新失敗時，Monoize 保留最後一次有效匯率。

## 儲值餘額

1. 選擇儲值商品，或輸入自訂金額。
2. 檢查儲值金額、贈送金額和實得金額。
3. 選擇一個已啟用的付款 Channel。
4. 建立訂單。

Monoize 在聯絡 Provider 前儲存付款嘗試。Stripe 隨後開啟其託管的 Checkout 頁面。

支付寶提交已簽章的官方付款表單。微信 Native 顯示可掃描的 QR Code。微信 H5 開啟官方行動付款頁面。

Provider 結果未知時，不要建立另一個付款嘗試。等待 Monoize 對帳現有付款嘗試。

Checkout 結束後，商店每兩秒檢查一次訂單。付款和履約完成、訂單關閉或訂單過期後，檢查停止。

在 `/dashboard/orders` 查看訂單。分別檢查付款狀態和履約狀態。

Monoize 僅在驗證 Channel 付款後發放餘額。管理員不能把未付款訂單標記為已付款或已履約。

## 設定 Stripe 回呼

把 Stripe Webhook 端點設為 `https://lynshen.org/api/store/callbacks/{channel_id}`。使用 Stripe Channel ID 取代 `{channel_id}`。

訂閱 `checkout.session.completed` 和 `checkout.session.async_payment_succeeded`。把端點簽章密鑰儲存在加密的 Stripe 憑證中。

## 設定支付寶回呼

把支付寶非同步通知網址設為 `https://lynshen.org/api/store/callbacks/{channel_id}`。使用支付寶 Channel ID 取代 `{channel_id}`。

在商店管理中儲存支付寶應用程式 ID、賣家 ID、商戶私鑰、支付寶公鑰和環境。Monoize 驗證 RSA2，並只在儲存已驗證事件後回傳 `success`。

## 設定微信支付回呼

把微信支付通知網址設為 `https://lynshen.org/api/store/callbacks/{channel_id}`。使用微信支付 Channel ID 取代 `{channel_id}`。

儲存商戶號、應用程式 ID、API v3 密鑰、商戶憑證序號、商戶私鑰、平台憑證序號和平台公開金鑰。Monoize 在履約前驗證平台簽章並解密付款資源。

## 購買方案

選擇方案和付款 Channel。一個方案可以同時套用多個額度週期。週期可以是 5 小時、12 小時、每日、每週、每月或自訂整數小時。

Monoize 以人民幣儲存方案額度。商店會把額度顯示為四捨五入後的整數人民幣或美元金額。

## 為 SQLite 啟用方案

變更 SQLite 配額 Gate 前，停止 Monoize 應用程式。把 `MONOIZE_DATABASE_DSN` 設為目標 SQLite 資料庫。

把已通過演練的 manifest 匯入 `next` 槽位：

```bash
monoize-store-ops quota-gate import --slot next --manifest ./quota-manifest.json
```

從命令輸出讀取相容性 fingerprint。啟動新應用程式版本前，推廣已匯入的 manifest：

```bash
monoize-store-ops quota-gate promote --expected-fingerprint <fingerprint>
```

此命令會拒絕 PostgreSQL、過大的 manifest、無效 JSON，以及與目前 SQLite 環境不相符的 manifest。

## 使用兌換碼

在**兌換碼**中輸入一個未使用的兌換碼。兌換碼可以增加餘額或啟用方案。兌換流程不使用付款 Channel，也不建立訂單。

## 管理商店

管理員開啟 `/dashboard/store-admin`。使用四個分頁管理商品、付款 Channel、訂單和兌換碼。

- 分別設定人民幣和美元的自訂儲值範圍。
- 新增支付寶、微信支付、Stripe 或 HTTP 草稿 Channel。使用內建圖示、HTTPS 圖片連結或上傳圖片。
- 開啟一個現有的官方 Channel。填寫全部憑證欄位和目前管理員密碼。選取**替換憑證**。Monoize 會加密新版本、停用舊版本並停用此 Channel。
- 在 Milestone 1 中保持 HTTP Channel 停用。
- 分別查看付款狀態和履約狀態。不要使用人工完成操作。
- 一次產生 1 至 20 個單次兌換碼。Monoize 顯示明文時立即保存。
- 在**付款管道**分頁標題列開啟**隱私記錄**和**保留策略**。
- 在官方 Channel 列選擇 **Governance**。開啟**支付合規**、**商戶能力**或**管道就緒狀態**。

## 隱私與資料治理

正式環境 checkout 和回呼需要目前已接受的 Store 隱私記錄。複審間隔不得超過 365 天。

在 `/dashboard/store-admin` 開啟**商店管理**。選擇**付款管道**分頁。選取**隱私記錄**。

檢視現有記錄。每筆記錄顯示政策版本、司法轄區、允許區域、接受狀態和下次複審日期。

核准策略更新後建立新記錄。輸入政策版本、司法轄區、允許區域、法律依據和證據 SHA-256 摘要。設定財務記錄保留天數、過期授權保留小時數和複審間隔。記錄建立後不可修改。

在該 Channel 列選擇 **Governance**。選取**管道就緒狀態**。透過該對話方塊關聯隱私記錄。若無隱私記錄，在就緒狀態空狀態中選取**開啟隱私記錄**。readiness profile 未引用目前已接受記錄時，Channel 保持不可用。

正式 checkout 還需要每個官方 Channel 的目前 Store 支付條款確認。

在該 Channel 列選擇 **Governance**。選取**支付合規**。檢視 Store 支付條款確認摘要和目前條款版本。勾選確認核取方塊。輸入 Admin 密碼。選取**確認目前條款**。

有效 Channel 可用性還需要目前商戶能力記錄。

在該 Channel 列選擇 **Governance**。選取**商戶能力**。選擇能力類型。設定狀態、環境、Provider 產品和證據摘要。Monoize 記錄驗證並設定到期時間。

以下保留週期適用於每筆記錄：

- 回呼原文：30 天
- 網路元資料（source IP 和 User-Agent）：90 天
- 兌換 reveal、copy 和 export 稽核：730 天
- 過期 reauthentication grant 雜湊：過期後 24 小時內

支付資料、回呼證據、備份、日誌和加密金鑰必須保留在隱私記錄的允許區域內。

每次證據讀取、匯出、保留覆寫和法律保留操作都會寫入不可變的存取稽核。

## 資料保留與刪除

Monoize 每天在 Store Primary 的 03:00 UTC 執行有界保留任務。Replica 不執行此任務。

開啟**商店管理**。選擇**付款管道**分頁。選取**保留策略**。

對話方塊顯示連續失敗次數、結帳暫停狀態、執行紀錄數和法律保留數。

需要立即清理時手動執行保留。輸入目前密碼和原因。選取**執行保留**。Monoize 依資料類別分批刪除或清除過期資料。

每次執行每個資料類別最多處理 500 筆未 hold 的根記錄。刪除財務根記錄時也會刪除關聯子記錄。有效 entitlement 不會被刪除。

執行成功後連續失敗次數重設為零。

## 法律保留與刪除失敗暫停

法律保留會暫停指定資料類別中特定識別碼的刪除。透過 `POST /api/dashboard/store/admin/retention/legal-holds` 建立保留。請求需要 scope 為 `legal_hold` 的五分鐘 reauthentication grant。

每個保留需要不同 approver、原因、請求機構、強制到期時間，以及 1 至 100 個識別碼。資料類別必須是以下之一：`raw_callback_bodies`、`network_metadata`、`financial_records`、`redemption_audits` 或 `expired_reauth_grants`。到期後保留自動停止。保留不會還原已刪除資料。延長保留需要建立新的審批記錄。

**保留策略**對話方塊顯示法律保留數，但不建立保留。

三次連續保留執行失敗後，Monoize 建立嚴重警示並暫停新結帳。現有訂單和 callback ingestion 繼續運作。新訂單和 payment attempts 回傳 HTTP `503`，code 為 `store_retention_paused`。

透過遏制清除結帳暫停。結帳暫停時開啟**保留策略**對話方塊。輸入目前密碼、原因和證據 SHA-256 摘要。選取**遏制警示**。Monoize 記錄遏制、標記警示為已遏制，並恢復結帳。後續執行再次失敗時結帳可能再次暫停。
